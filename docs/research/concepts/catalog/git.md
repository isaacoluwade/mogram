# Git & version control

Stage 1 catalog for the **Git** area: every major concept a developer meets using Git and hosted Git,
checked against the Pro Git book, the git-scm reference, GitHub Docs, GitLab Docs, Atlassian's Git
tutorials and trunkbaseddevelopment.com.

## Scope

**In:**

- Git's model, as far as it explains behaviour: snapshots, the object store, content addressing,
  the commit graph, refs, HEAD, packfiles.
- Local work: working tree, index and repository; commits; ignoring files; stash; worktrees.
- Branching and merging: branches, fast-forward and three-way merges, conflicts and how to resolve
  them, merge strategies.
- Rewriting and undoing history: rebase, interactive rebase, amend, cherry-pick, revert, reset,
  reflog, whole-history rewrites.
- Remotes: clone, remote-tracking branches and upstreams, fetch, pull, push, force-push, forks,
  authenticating to a remote.
- Collaborating on hosted Git: the features GitHub, GitLab, Bitbucket and Azure Repos share (pull or
  merge requests, review, merge methods, branch protection, status checks, CODEOWNERS, merge queues,
  stacked PRs). Where a host has its own name for something, the row gives it.
- Branching workflows: feature branches, trunk-based development, GitHub flow, GitFlow, release
  branches, environment branches.
- History hygiene and releases: linear history, atomic commits, signed commits, tags, semantic
  versioning.
- Investigating history: commit ranges, blame, bisect.
- Large repositories and repository structure: monorepo vs polyrepo, submodules, subtree, Git LFS,
  shallow clone, partial clone, sparse checkout.
- Hooks and `.gitattributes`.

**Left to other areas:**

- **Delivery**: CI/CD pipelines, feature flags, branch by abstraction, deployment and release
  strategies (canary, blue-green), GitOps, artifact promotion.
- **Security**: secret scanning and push protection, dependency review, supply-chain attestations
  (SLSA, Sigstore beyond signing commits), managing tokens and SSH keys.
- **Architecture**: monolith vs microservices, and how services map to repositories (the
  monorepo-vs-polyrepo row here covers only the source-control side).
- **Azure / AWS / Google Cloud**: anything a platform does differently with Git hosting (Azure Repos
  branch policies, AWS CodeCommit, Google Secure Source Manager), and only where the generic concept
  here isn't enough.

Every concept here is `any`: Git and the hosted-Git features catalogued are the same on every cloud.

| git-branch              | Branch                               | 1    | any      | A branch is a lightweight, movable pointer (a ref) to a commit. Creating one writes one small file, and each commit on it moves the pointer forward.                                                                                                                                                          | Branches are cheap labels, not copies of the code. ### Deliberately left out, and why

- **Setup and personal configuration** (installing, `git config` levels, aliases, editors, GUIs, shell
  prompts): needed once, not ideas that need animating.
- **Self-hosting a Git server** (daemon, smart HTTP setup, GitWeb, instaweb, installing GitLab): most
  teams use hosted Git. The protocol ideas are in git-remote-authentication and git-packfiles.
- **Email patch workflow** (`format-patch`, `am`, `send-email`, `request-pull`) and the dictator and
  lieutenants workflow: real, but limited to a few very large open-source projects. The contribution
  idea is in git-fork.
- **Migrating from SVN or Perforce**: one-off projects. The difference that matters is in
  git-distributed-version-control.
- **Small utilities with no new mental model**: `notes`, `replace`, `bundle`, `archive`, `fsck`,
  `shortlog`, `show`, `grep`, `range-diff`, `instaweb`, gitk.
- **Storage internals with no visible change in behaviour**: the reftable backend, commit-graph files,
  fsmonitor, Scalar and `git maintenance`.
- **Separate rows folded into others:**

  | Diffing the three areas    | git-three-areas              |
