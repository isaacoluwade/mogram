# Azure: concept catalog

Stage 1 research for the Azure area. Names, defaults and retirement dates are as of October 2026
(Microsoft Entra rather than Azure AD, Microsoft Foundry rather than Azure AI Foundry, Flex
Consumption as the serverless Functions plan, Azure Managed Redis replacing Azure Cache for Redis).

## 1. Scope

**In:** what Azure names, organises, implements or does differently, and the "which Azure
service do I use" decisions people struggle with:

- How Azure is organised and driven: the tenant, management group, subscription and resource
  group hierarchy; Azure Resource Manager as the single control plane; control plane vs data
  plane as Azure enforces it.
- Governance: Azure RBAC, Entra roles vs Azure roles, Azure Policy, resource locks, landing
  zones, the Cloud Adoption and Well-Architected frameworks.
- Identity as Microsoft Entra implements it: tenants, hybrid sync, app registrations and service
  principals, managed identities, workload identity federation, Conditional Access, PIM,
  external identities, Agent ID.
- Azure networking: VNets, NSGs, routing, peering, hub-spoke and Virtual WAN, Private Link and
  its DNS, the load-balancer family, outbound connectivity, VPN and ExpressRoute, Bastion.
- Azure's hosting options (VMs, App Service, Functions, Container Apps, AKS), storage accounts,
  Azure SQL, Cosmos DB, the analytics services, the messaging and integration services,
  Azure Monitor, Key Vault, Defender for Cloud, Sentinel, Backup and Site Recovery, pricing
  discounts and Cost Management, ARM/Bicep deployments, Arc, Migrate, Foundry and AI Search.

**Left to other areas:** the idea underneath each of these, explained the same on any cloud.
What load balancing, DNS, TLS, BGP and VPNs are (Networking); OAuth, OIDC, SAML, MFA, Zero
Trust, RBAC and ABAC as models, envelope encryption (Security); consistency models, replication,
partitioning, backup and restore (Data); queues, pub/sub, streams, delivery guarantees,
dead-lettering, sagas (Messaging); Kubernetes itself, images and registries (Containers); CI/CD,
IaC, GitOps, feature flags (Delivery); logs, metrics, traces, OpenTelemetry, alerting principles
(Observability); service models, regions and zones in general, shared responsibility, pricing
models in general, SLA arithmetic (Fundamentals, Reliability); RAG, vector search, model serving
and agents (AI systems); architecture styles and cloud design patterns (Architecture).

**Boundary rule used:** a concept is here when explaining it needs Azure's own names, defaults,
limits or product choices. If it would be explained the same way on AWS or Google Cloud, it
lives in that area and appears here only under Overlaps.

Every row's Platform is `azure`.

### 3.4 Networking

| azure-vnet-subnets                         | Virtual networks and subnets                                                                    | 1    | azure    | A VNet is a private, regional, software-defined network with one or more address spaces split into subnets. Subnets span every zone in the region, Azure reserves five addresses in each, routes between all subnets by default, and some services need dedicated, specially named or delegated subnets (GatewaySubnet, AzureFirewallSubnet, AzureBastionSubnet).                                                                                                                                                      | A VNet is a routing and isolation boundary, not cabling: there's no broadcast, Azure's software router handles every hop, and new VNets now get private subnets with no implicit internet access.                                                                         | On-premises VLANs; AWS VPC subnets (one AZ each, where Azure subnets are regional)      |
| azure-nsg                                  | Network security groups and application security groups                                         | 1    | azure    | Stateful allow and deny rules, evaluated by priority, using addresses, service tags or ASGs, attached to subnets and/or NICs. Inbound traffic must pass the subnet NSG then the NIC NSG; outbound, the reverse. ASGs let rules say "web to db" instead of listing IPs. Network Watcher shows effective rules and flow logs.                                                                                                                                                                                            | An NSG isn't a box traffic passes through; it's a filter applied at every NIC, so both layers must allow a flow, and the effective rules are what actually apply.                                                                                                         | Azure Firewall; AWS security groups (allow-only) and NACLs                              |
| azure-network-security-layers              | NSGs and ASGs vs Azure Firewall vs WAF vs DDoS Protection                                       | 2    | azure    | Azure's network defences each work at a different layer and place. WAF policies on Front Door or Application Gateway block web attacks. Azure Firewall (Basic, Standard, Premium with TLS inspection and IDPS) centrally inspects egress, east-west and hybrid traffic with DNAT, network and FQDN rules. NSGs filter at every subnet and NIC. | No single service is "the firewall": a web request meets DDoS, then WAF, then optionally Azure Firewall, then NSGs, and each stops attacks the others can't see. | azure-hub-spoke                            | Hub-and-spoke topology                                                                          | 2    | azure    | A hub VNet holds shared services (Azure Firewall or an NVA, VPN and ExpressRoute gateways, Bastion, DNS resolver) and each workload spoke peers to it, uses its gateways and sends traffic through its firewall with UDRs. | azure-virtual-wan                          | Azure Virtual WAN                                                                               | 3    | azure    | A Microsoft-managed network with a hub per region containing a router, site-to-site, point-to-site and ExpressRoute gateways and optionally Azure Firewall (a secured virtual hub). | azure-private-endpoint-vs-service-endpoint | Private Endpoint vs Service Endpoint (Private Link)                                             | 1    | azure    | A private endpoint is a NIC with a private IP in your subnet, mapped to one specific PaaS resource (or to your own service published with Private Link service), reachable from peered and on-premises networks. Only private endpoints work from on-premises and pin access to one resource, which stops data going to someone else's account. | Each other; App Service VNet integration; Private Link service                          |
| azure-private-endpoint-dns                 | Private endpoint DNS and DNS Private Resolver                                                   | 2    | azure    | PaaS names have a CNAME to a privatelink zone.
