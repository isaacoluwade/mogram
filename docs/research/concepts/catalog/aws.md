# AWS: concept catalog

Stage 1 (research) for the **AWS** area. It lists what is specific to Amazon Web Services and
deserves its own animated explanation, checked against the current AWS certification exam guides,
the AWS decision guides and the core AWS whitepapers. Researched October 2026; every row has
Platform `aws`.

103 concepts in 17 groups: 18 at tier 1, 74 at tier 2, 11 at tier 3.

## 1. Scope

**In.** A concept belongs here when the mechanism, the name or the choice is AWS's own:

- **How AWS implements a general idea.** Security groups vs NACLs, Route 53 routing policies,
  KMS envelope encryption, the Lambda execution environment, Aurora's shared storage.
- **How AWS organises things.** Accounts, Organizations, OUs, SCPs and RCPs, landing zones,
  resource scope (global, Regional, zonal), IAM roles and trust policies.
- **Where AWS differs from other clouds.** VPC subnets are per AZ, a "public" subnet is defined
  only by its route table, cross-AZ traffic is billed, the root user, AZ names vs AZ IDs.
- **The "which AWS service do I use" comparisons people get stuck on.** ALB vs NLB vs GWLB,
  SQS vs SNS vs EventBridge, ECS vs EKS × EC2 vs Fargate, Kinesis vs Firehose vs MSK, EFS vs FSx
  vs S3 Files, Secrets Manager vs Parameter Store, Bedrock vs SageMaker, Direct Connect vs VPN,
  CloudTrail vs CloudWatch vs Config.

**Left to other areas.** The general idea behind an AWS concept lives in its home area and is listed
under **Overlaps** (§5): what a region or AZ is, and shared responsibility (Fundamentals); DNS, TLS,
NAT, subnets, BGP and how load balancing works (Networking); RBAC/ABAC, OAuth/OIDC/SAML, envelope
encryption in general, zero trust (Security); replication, partitioning, consistency, caching
strategies, data lakes (Data, Scaling); queue and stream semantics, sagas (Messaging); Kubernetes
objects (Containers); DR tiers, RTO/RPO and static stability in general (Reliability); CI/CD and
IaC in general (Delivery); serving models and RAG (AI systems).

**This is not a service catalogue.** A service gets its own row only when it needs explaining.
Services that are just "a managed X" (DocumentDB, Keyspaces, Neptune, Timestream, OpenSearch, MQ,
MWAA, Redshift, EMR) appear only inside comparison concepts. The concept that covers a folded item
is named in the Coverage check (§4).

### 3.4 VPC networking and hybrid connectivity

| aws-vpc-anatomy                     | VPC anatomy                                                            | 1    | aws      | A VPC is a Regional private network with one or more CIDR blocks, divided into subnets that each sit in a single AZ. | aws-security-groups-vs-nacls        | Security groups vs network ACLs                                        | 1    | aws      | Security groups are stateful, allow-only firewalls on each network interface. | aws-vpc-connectivity-options        | Connecting VPCs: peering vs Transit Gateway vs PrivateLink vs sharing  | 2    | aws      | VPC peering: 1:1 and non-transitive. Choose by need: whole networks talking (Transit Gateway); one service across overlapping CIDRs (PrivateLink or Lattice); or fewer VPCs (sharing). Transit Gateway route-table association and propagation is how prod and dev are kept apart. | Direct Connect gateway; Site-to-Site VPN                                                          |
| aws-vpc-endpoints-and-privatelink   | VPC endpoints: gateway vs interface (PrivateLink)                      | 2    | aws      | Gateway endpoints (S3 and DynamoDB only, free) add a prefix-list route to route tables. Gateway endpoints work only from inside the VPC; interface endpoints are also reachable from on-premises and peered networks. Endpoint policies limit what can be reached through them.                                                              | NAT gateway; VPC peering                                                                          |
| aws-direct-connect-vs-vpn           | Direct Connect vs Site-to-Site VPN                                     | 2    | aws      | Two hybrid links. Client VPN is for people, not sites.                                                                        | Transit Gateway; Verified Access                                                                  |
| aws-direct-connect-vifs-and-gateway | Direct Connect virtual interfaces and DX gateway                       | 3    | aws      | A DX connection carries VLAN-tagged virtual interfaces, each with its own BGP session. ### Whitepapers

- **Well-Architected Framework** → aws-well-architected-framework. Pillar-level practices are spread

- **Organizing Your AWS Environment Using Multiple Accounts** → aws-organizations,
  aws-landing-zone-and-control-tower (recommended OUs and accounts), aws-scps-and-rcps,
  aws-data-perimeter.
- **Disaster Recovery of Workloads on AWS** → aws-dr-strategies (four tiers, data plane vs control
  plane), aws-multi-region-databases (write global, write local, write partitioned),
  aws-application-recovery-controller, aws-backup, aws-s3-replication.

### Deliberately excluded (summary)

- **Commercial and support programmes:** Support plans, Partner Network, Marketplace, re:Post,
  Health Dashboard, AWS CAF. These are useful to know about but have no mechanism to animate.
- **AI API services:** Rekognition, Comprehend, Lex, Polly, Textract, Transcribe, Translate, Kendra
  (in maintenance), Q Business (in maintenance). Each is "an API that does X"; serving models
  belongs to AI systems.
- **Out of cloud-infrastructure scope:** end-user computing (WorkSpaces, AppStream), Connect, SES,
  Amplify, IoT, and the developer AI assistants (Q Developer, Kiro, DevOps Agent, Security Agent).
- **Covered by general concepts in other areas:** OpenSearch, Redshift internals, EMR, Neptune,
  DocumentDB, Keyspaces and Timestream (Data); MQ and MWAA (Messaging); FIS and Resilience Hub
  (Reliability); Verified Access and Verified Permissions (Security); AppConfig (Delivery).
- **Folded into another concept to avoid padding:** Lightsail, Batch, Outposts, Local Zones,
  Wavelength, Spot, Savings Plans vs RIs, ABAC, IMDSv2, SigV4, Access Analyzer, Directory Service,
  Roles Anywhere, RDS Proxy, RDS PITR, DAX, MemoryDB, Aurora Serverless v2, Aurora DSQL, Lambda
  durable functions, CloudFront Functions vs Lambda@Edge, Cloud WAN, VPC Lattice, VPC sharing, IPAM,
  StackSets, SAM, Elastic Disaster Recovery, AWS Transform, and DMS with Schema Conversion. Each
  lives inside the concept named in the tables above.
- **Specialist niche:** TGW Connect and SD-WAN, TGW multicast, MTU and jumbo frames, Payment
  Cryptography, Service Catalog, License Manager, Billing Conductor, and Nitro or inter-node
  encryption details.
- **Legacy or closed to new customers:** App Mesh (end of support Sep 30 2026), App Runner, Snow
  Family, Glacier vaults, Migration Hub and Classic Load Balancer. Each is mentioned only as legacy
  where it helps explain its successor.
